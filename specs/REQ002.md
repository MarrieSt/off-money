# Money App – Emma Google Sheets Ingestion Specification

## Objective

Enable the Money application to ingest transaction data from the existing Google Sheet populated by Emma.

Architecture:

```text
Emma
    ↓
Google Sheets
    ↓
Google Sheets API (Service Account)
    ↓
Django Import Service
    ↓
Raw Import Layer
    ↓
Canonical Transaction Model
    ↓
Future Analytics / Dashboards
```

This iteration focuses only on ingestion, persistence and operational tooling.

---

# Authentication

- Use a Google **Service Account**.
- Use the **Google Sheets API** with **read-only** access.
- Do **not** use OAuth login.
- Do **not** use the existing Places API key.

Required packages:

- google-auth
- gspread

OAuth Scope:

```
https://www.googleapis.com/auth/spreadsheets.readonly
```

# Models

## ImportRun

Track every import execution.

Fields:

- source
- status
- started_at
- finished_at
- rows_read
- rows_created
- rows_updated
- rows_skipped
- rows_failed
- error_message

Statuses:

- running
- success
- partial
- failed

Expose in Django Admin.

---

## EmmaRawTransaction

Fields:

- import_run
- source_row_number
- source_hash
- raw_data (JSONField)
- first_seen_at
- last_seen_at
- created_at
- updated_at

Store the original Google row in JSON.

Generate a deterministic SHA256 hash from a normalised row.

Do **not** use spreadsheet row number as a unique identifier.

---

## Transaction

Populate the existing canonical transaction model.

Suggested fields:

- transaction_date
- posted_date
- description
- merchant_name
- amount (Decimal)
- currency
- account_name
- category
- transaction_type
- source = "emma"
- source_reference
- raw_transaction

Unknown fields remain inside raw_data.

## emma_import.py

Responsibilities:

- Create ImportRun
- Fetch rows
- Normalise data
- Generate hashes
- Store EmmaRawTransaction
- Create/update Transaction
- Update ImportRun statistics

Public API:

```python
run_emma_import()
```

---

# Import Behaviour

Requirements:

- Idempotent
- No duplicate transactions
- Preserve raw data
- Continue processing if individual rows fail
- Do not fail the whole import because of one bad row

Normalise before hashing:

- trim whitespace
- normalise nulls
- normalise dates
- normalise numeric strings
- stable JSON ordering

Clarifications

Q: Emma's Primary sheet has an `ID`; should canonical transactions upsert by `(user, source_system, source_transaction_id)` and use the normalized SHA256 only to detect row-content changes?
A: Yes, Emma ID is identity - Edits update the same transaction; hashes detect changed source content.
Q: If a row references an account that is not yet mapped to a FinancialAccount, what should the importer do?
A: Fail that row; map in Admin - Keep imports auditable and avoid silently creating accounts.
Q: How should the importer choose the Money user who owns each ImportRun and its transactions?
A: One configured user - Use a required username/user ID setting for the personal Emma sheet.
Q: If an imported Emma row has a blank `ID`, should it be treated as a row failure rather than using its content hash as a transaction identity?
A: Fail the row - Avoid accidentally merging two legitimate identical purchases.
Q: Should EmmaRawTransaction keep only the latest source row per Emma ID, or retain a snapshot of that row on every import?
A: Latest row only - Update raw_data/hash and last_seen_at; simpler and matches the proposed fields.
Q: I’ll have imports create missing accounts from Emma’s Account and Bank values, defaulting currency to MONEY_DEFAULT_CURRENCY. Is that what you mean?
A: Yes, auto-create - The importer owns account discovery; no manual Admin seeding.
Q: I’ll have imports create missing accounts from Emma’s Account and Bank values, defaulting currency to MONEY_DEFAULT_CURRENCY. Is that what you mean?
A: Yes, auto-create - The importer owns account discovery; no manual Admin seeding.


Emma IDs identify canonical transactions; normalized SHA256 values detect changes. Rows without IDs fail individually. The importer targets the user configured by `MONEY_IMPORT_USERNAME` and retains the latest raw-row version per Emma ID. It automatically creates missing accounts using the sheet's Account and Bank values for that user; account currency defaults to `MONEY_DEFAULT_CURRENCY`, while transaction currency comes from each row.
