# Daily Spend Widget — Functional & UX Specification

## 1. Purpose

Create a reusable dashboard widget that visualises **money spent over time** using a **stacked column chart**.

The widget should answer:

- How much did I spend today?
- How does today's spending compare with recent days?
- What did I spend the money on?
- Which accounts did the spending come from?
- How has my spending changed across recent weeks or months?
- Can I move backwards through history without configuring custom dates?

The widget is intended to be a primary analytical component on the Money dashboard.

---

## 2. Core Chart

Use a **vertical stacked column chart**.

Each column represents one time bucket:

- Day
- Week
- Month

The total column height represents **total amount spent during that period**.

Individual coloured segments represent either:
- Spend categories
- Accounts

depending on the selected **Stack by** mode.

Do not use a line chart.

---

## 3. Header

```
Spending                              [Day | Week | Month]

£1,284.32
Total spent · 28 Sep – 4 Oct

Stack by: [Category ▾]

                ‹    28 Sep – 4 Oct    ›
```

The total displayed beneath **Spending** is the total spend for the currently displayed window.

---

## 4. Time Granularity

Segmented control:

```
[ Day ] [ Week ] [ Month ]
```

Default: **Day**

Always display **7 buckets**.

### Day
Today + previous 6 calendar days.

### Week
Current week + previous 6 calendar weeks.

Weeks run Monday → Sunday.

### Month
Current month + previous 6 calendar months.

Current week/month are always month-to-date/week-to-date.

---

## 5. Historical Navigation

Navigation:

```
‹    28 Sep – 4 Oct    ›
```

Moves exactly one 7-bucket window backward or forward.

Cannot navigate into the future.

When viewing historical periods show:

```
[Current]
```

or

```
[Today]
```

to jump back.

---

## 6. Stack By

Selector:

```
Stack by: [Category ▾]
```

Options:

- Category (default)
- Account

Changing this must not reset the selected period.

---

## 7. Category Behaviour

- Stable colours across all periods.
- Maximum of seven visible series.
- Display Top 6 + Other.
- Ranking determined across the currently displayed seven-bucket window.

---

## 8. Account Behaviour

Same behaviour as categories:

- Stable colours
- Top accounts shown
- Remaining grouped into Other

---

## 9. Legend

Legend displayed beneath chart.

Ordered by highest total spend.

Legend items are clickable to isolate a category/account.

Provide **Show all** when filters are active.

---

## 10. Tooltips

Hovering a column displays:

- Date/period
- Total spend
- Breakdown by category/account
- Values sorted largest to smallest

Hovering a segment highlights that segment while still displaying the complete breakdown.

---

## 11. Drill-down

Clicking a column opens transactions for that period.

Clicking a stack segment opens transactions filtered by both:

- period
- category/account

Preferred implementation: side drawer.

---

## 12. Empty / Loading / Error States

Loading:
- Skeleton chart.

Empty:
- "No spending in this period"

Error:
- "Unable to load spending"
- Retry button.

---

## 13. Data Rules

Include:
- Spending transactions

Exclude:
- Income
- Transfers
- Balance adjustments
- Duplicates
- Excluded transactions

Refunds reduce spend according to application rules.

Aggregation must happen server-side.

---

## 14. API

GET

```
/api/analytics/spending
```

Parameters:

- granularity=day|week|month
- stack_by=category|account
- end_date=YYYY-MM-DD

Returns one aggregated seven-bucket dataset.

---

## 15. Performance

One API request per widget refresh.

Aggregate in PostgreSQL.

Use indexes on:

- transaction_date
- category
- account

Cache recent requests client-side.

## 17. Responsive Behaviour

Desktop:
- Full experience.

Tablet:
- Same controls with reduced spacing.

Mobile:
- Compact labels.
- Tap replaces hover.

---

## 18. UX Principles

The widget should answer:

1. What have I been spending?
2. Where did it go?
3. Which transactions caused it?

Avoid unnecessary configuration.

No custom date picker in the default dashboard widget.

---

## 19. Acceptance Criteria

- Stacked vertical column chart.
- Default = Today + previous six days.
- Day / Week / Month supported.
- Seven buckets always shown.
- Historical navigation.
- Future disabled.
- Current shortcut.
- Stack by Category / Account.
- Stable colours.
- Top 6 + Other.
- Interactive legend.
- Rich tooltips.
- Transaction drill-down.
- Zero-spend periods remain visible.
- Server-side aggregation.
- Responsive layout.
- Loading, empty and error states implemented.

clarifications

Q: Transactions can contain currencies other than GBP, but the widget shows one £ total. How should it handle mixed currencies?
A: GBP only - Aggregate GBP transactions only and label totals clearly; omit other currencies.
Q: What should count as spend, including refunds?
A: Purchase baseline + rules - Start with negative Purchase rows; exclude other types, respect account analytics flag and active SpendRules; linked positive refunds reduce spend.
